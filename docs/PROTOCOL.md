# EmergencyMesh protocol v1

Frozen implementation contract, November 7, 2026. Separate from ScrabbleBot and Relay. Hackathon prototype, with no real dispatch integration enabled.

## Radio envelope

All multibyte integers are little endian. Max complete LoRa frame: 220 bytes. Bytes 0..15 are header: ASCII `EM` (2), version `1` (1), type (1: request, 2: receipt), region uint16, origin uint32, sequence uint32, remaining hops uint8 (0..4), key ID uint8. Then random 12-byte nonce, AES-256-GCM ciphertext, 16-byte tag. AAD is header bytes 0..13 concatenated with byte 15. Only byte 14 may change on relay. Reject invalid magic/version/type/hop/size before forwarding. Relays cannot authenticate/decrypt; hub/phone must authenticate before storing or accepting receipts. Region and key ID must match configured provisioned values. Request identity is region/origin/sequence; replay entries also retain frame digest, never accept differing payloads as the same request. Retries reuse identical encrypted bytes (no nonce reuse with new plaintext). Random nonce per new encryption. Max hops 4, initial 3. Demo uses a private shared regional key; possession allows impersonation, no per-user identity/revocation guarantee. No hardcoded real key.

## Request plaintext

Byte 0 category (1 medical, 2 fire, 3 rescue, 4 safety, 5 supplies); byte 1 user-reported severity (1 urgent, 2 serious, 3 assistance); byte 2 people (1..255); byte 3 flags (1 location known, 2 breathing concern, 4 trapped, 8 severe bleeding; no other bits); bytes 4..7 creation Unix seconds uint32; bytes 8..11 latitude int32 scaled 1e5; bytes 12..15 longitude int32 scaled 1e5; bytes 16..17 location accuracy meters uint16 (65535 unknown); byte 18 phone battery (0..100 or 255 unknown); byte 19 note UTF-8 byte length; remaining note max120 bytes. Coordinates must be zero and accuracy65535 when location flag is absent. Known location must be in valid geographic ranges. Text must be valid UTF-8, length exact, no silent truncation. Total request plaintext 20..140 bytes. Largest encrypted request184 bytes. The priority shown is supplied by the user; AI cannot change it.

## Receipt plaintext

Original request origin uint32, original request sequence uint32, status uint8 (1 hub received, 2 operator reviewed), UTF-8 text byte length uint8, text max80 bytes. Hub origin/sequence in envelope are its own IDs, not request IDs. The app accepts only authenticated receipts referencing its known request. No status means emergency services dispatched. Operator-reviewed is a human demo-console action. Duplicate/retried requests should resend the existing receipt without creating another incident. Hub ACK precedes optional local-model summarization.

## BLE

Nordic UART service `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`; phone writes RX `...0002...` WITH RESPONSE, subscribes TX `...0003...` notifications. Each ATT value max20 bytes: marker0xE1, transferID uint8, chunkIndex uint8 zero-based, chunkCount uint8 (1..14), then1..16 frame bytes. All nonfinal chunks exactly16 bytes. Reassemble indexed chunks for one transfer, bounded220 bytes, expire after5seconds. TransferID only identifies fragmentation, not message identity. Send sequentially, respect write responses. Frames are opaque; app encrypts and hub decrypts. TX carries the same framed encrypted receipt via BLE. Local write completion means submitted to device, never hub receipt. Firmware queues complete frames and reports link/radio problems over serial only; no fake BLE delivery ACK. Retry at10,25,45 seconds, then show unconfirmed and offer explicit retry. Persistent encrypted outbox supports reconnect/relaunch.

## USB serial hub

115200 baud, newline-delimited JSON, max1024 bytes/line. Host sends `{"op":"tx","frame":"<base64>"}`; board emits `{"op":"rx","frame":"<base64>","rssi":-70,"snr":7.0}`. Host may query `{"op":"status"}` after opening a port. Board emits/replies `{"op":"ready","node":123,"role":"hub","frequency":915,"protocol":1,"region":1,"keyId":1,"radioReady":true}` or bounded diagnostics `{"op":"error","code":"..."}` and `{"op":"queued"}`. An open OS port means USB available only; the hub enables transmit only after matching typed readiness metadata with radioReady true. A ready line is a board self-report, not evidence of RF or phone delivery. Queued means accepted locally, not transmitted or delivered. USB debug lines must never be parsed as frames. Hub/relay/companion firmware share envelope checks. Firmware managed flood uses expiring duplicate cache, randomized relay delay, hop decrement, bounded TX queue/rate and no recursive rebroadcast. Locally submitted retries may rebroadcast identical frames after backoff; receiver duplicate cache suppresses loops but must permit retries after a short cooldown so lost receipts can recover. Hub-origin serial TX is sent to radio and BLE as appropriate. All radio nodes must use identical PHY and regional profile.

## Initial hardware profile

LILYGO T3 LoRa32 V1.6.1 ESP32/SX1276, standard (not TCXO): SCK5 MISO19 MOSI27 NSS18 RESET23 DIO0=26 DIO1=33; LED25; OLED SDA21 SCL22 address0x3c. Verify actual radio variant/label before flash or RF. Initial US demo profile915MHz, bandwidth125kHz, spreading factor7, coding rate4/5, syncword0x12, power10dBm, CRC enabled, explicit header, preamble8. No RF regulatory certification claimed. Build separate SX1278 433MHz environment only with matching hardware. TCXO variant needs a separate pin/clock profile, not this default. Attach matching antenna before transmitting.

## Provisioning and boundaries

Hub CLI creates random regional32-byte key, region1/keyID1 and random phone origin; iOS stores key in Keychain. Manual import is demo provisioning, performed privately. Firmware has no encryption key. Hub binds127.0.0.1, serves local operator UI with session authentication and rejects cross-origin mutating requests. Raw requests are untrusted data, including instructions inside notes. Local optional Ollama at127.0.0.1 may propose a summary; deterministic original fields remain authoritative. No cloud inference, medical advice, automatic triage or real emergency-service calls. Dispatch export requires operator review and is marked simulation.
